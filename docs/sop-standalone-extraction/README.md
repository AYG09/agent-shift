# SOP 독립 앱 분리 문서 세트

## 1. 문서 목적

이 문서 세트는 현재 `agent-shift` 저장소 안에 있는 **SOP 프로토타입을 별도 저장소의 독립
웹앱으로 분리**하고, 그 앱이 **사내 서버망에서 자체 AI 연결로 동작**할 수 있게 만들기 위한
구현 기준이다.

분리 이유는 두 제품이 이미 사실상 별개이기 때문이다. 실측 결과 `/flow`는 SOP를 **한 번도
참조하지 않고**(0건), SOP는 공유 모듈 8개에만 의존한다. 서로 다른 사용자, 다른 배포 대상,
다른 보안 요구를 가진 코드가 한 저장소·한 배포 단위에 묶여 있는 상태다.

이 단계에서는 애플리케이션 코드를 변경하지 않는다. 무엇을 옮기고 무엇을 남기며, 옮긴 뒤
무엇이 달라져야 하는지를 검증 가능한 언어로 정의한다.

## 2. 확정된 방향 (2026-08-26)

| 결정 | 값 | 근거 |
|---|---|---|
| 분리 형태 | **별도 저장소로 완전 분리** | 사내 서버망 이전이 목적이므로 저장소 경계가 배포·보안·감사 경계와 일치해야 한다 |
| AI 연결 대상 | **미정 — 교체 경계만 정의** | 사내 인프라·모델 정책이 확정되지 않았다. 문서는 교체 지점과 계약만 고정하고 구체 모델·엔드포인트는 보류로 남긴다 |

이 두 결정은 사용자가 명시적으로 확정한 것이다. 이후 문서는 이를 전제로 작성한다.

## 3. 적용 우선순위

충돌 시 다음 순서를 적용한다.

1. 이후 확정되는 명시적 사용자·고객 결정
2. 이 문서 세트
3. `.agents/skills/implement-sop-customer-requirements/`의 reference 5개 (SOP 도메인 계약)
4. `docs/sop-member-context-redesign/`의 재설계 문서 (구성원 진입 UX 계약)
5. `docs/QUALITY_CONVENTIONS.md`, `docs/DESIGN_CONVENTIONS.md`
6. 현재 프로토타입 구현과 fixture

**이 분리는 SOP 도메인 계약을 하나도 폐기하지 않는다.** 승인 생애주기, Activity–Sub Action,
Agent화 판단 분리, 노드 작성 계약, HR 분석, 구성원 진입 흐름은 그대로 이식된다. 바뀌는 것은
**어디에 살고, 어떻게 배포되고, AI와 저장소에 어떻게 연결되는가**뿐이다.

## 4. 문서 구성

| 문서 | 역할 | 구현 전 필수 |
|---|---|---|
| [CONTEXT.md](CONTEXT.md) | 실측 결합도, 문제 정의, 용어, 가정과 보류 범위 | 필수 |
| [EXTRACTION_SPEC.md](EXTRACTION_SPEC.md) | 무엇을 옮기고 무엇을 남기는가 — 파일 인벤토리, 공유 모듈 처리, 수용 기준 | 필수 |
| [RUNTIME_AND_DEPLOYMENT.md](RUNTIME_AND_DEPLOYMENT.md) | 사내망 런타임 계약 — 빌드·실행·환경변수·영속성·네트워크 경계 | 필수 |
| [AI_PROVIDER_CONTRACT.md](AI_PROVIDER_CONTRACT.md) | provider 교체 경계, 키 관리 전환, 실패·예산 계약 | 필수 |
| [PARALLEL_EXECUTION.md](PARALLEL_EXECUTION.md) | 병렬 세션 소유권·선행 관계·통합 게이트 | 병렬 작업 시 필수 |

작업지시서는 이 다섯 문서를 소스 오브 트루스로 삼아 별도로 작성한다. 작업지시서가 이 문서의
보류 항목을 임의로 확정해서는 안 된다.

## 5. 완료 경계

엔지니어링 문서 구축 완료는 다음을 의미한다.

- 이관 대상과 잔류 대상이 파일 단위로 식별되어 있다.
- 공유 모듈 8개 각각에 대해 복사·분기·재작성 중 무엇을 할지와 그 근거가 정해져 있다.
- `src/app/api/ai/route.ts`의 SOP 분해 방법이 정의되어 있다.
- 사내망 런타임이 요구하는 것(빌드 산출물, 환경변수, 영속성, 외부 통신)이 명시되어 있다.
- BYOK에서 서버측 키 관리로의 전환 계약이 정의되어 있다.
- provider 교체 지점과 그 계약이, 구체 모델을 확정하지 않은 채로 정의되어 있다.
- 분리 후 무엇이 통과해야 "동등하다"고 말할 수 있는지가 실행 가능한 기준으로 있다.
- 병렬 세션이 같은 파일을 동시에 수정하지 않도록 소유권과 통합 순서가 정의되어 있다.

**완료 범위가 아닌 것**: 실제 파일 이동, 새 저장소 생성, 사내망 배포, AI 연결 구현, 성능
측정, 보안 감사.

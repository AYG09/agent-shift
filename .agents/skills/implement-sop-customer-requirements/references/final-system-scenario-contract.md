## 2. 검증된 고객 시나리오

### 2.1 구성원 첫 화면

- 이름, 사번, 조직, 직급, 주요 직무를 표시한다.
- SOP 상태별 건수 `작성 중 / 승인 요청 중 / 승인 완료 / 반려`를 표시한다.
- 나의 Task, Activity, Skill 수를 표시한다.
- 다음 활성 생성 경로를 제공한다.
  1. Task 기반 생성
  2. 동료 SOP 기반 생성
  3. 기존 내가 작성한 내용 기반 생성
- 실무 자료 기반 생성은 파일 업로드·영상 캡처를 언급하지만 향후 단계인 TBD로 표시한다.

원문은 “3가지”라고 쓰고 네 항목을 열거한다. 구현에서는 이를 `활성 경로 3개 + 비활성 TBD 카드 1개`로 해석한다. TBD 경로에 업로드 input, 저장소, OCR, 영상 처리 API를 만들지 않는다.

### 2.2 Task 기반 생성

1. 구성원이 “내가 하는 일”을 약 5문장 내외 자연어로 입력한다.
2. AI가 입력 내용과 소속·직무 정보를 이용해 Task Library 후보를 추천한다.
3. 구성원이 추천 Task를 명시적으로 선택한다.
4. 선택 Task의 Activity와 Skill을 불러와 Work Map을 구성한다.
5. 구성원이 Activity와 Skill을 선택·삭제·추가·수정한다.
6. 확정된 Task·Activity·Skill과 업무 맥락을 바탕으로 Task 단위 SOP 초안을 생성한다.
7. SOP는 `Task → Activity → Sub Action` 구조와 Sub Action별 AI Agent화 가능성 정보를 포함한다.
8. 구성원이 항목을 추가·삭제·수정하고 임시 저장한다.
9. 작성 완료 후 승인 요청한다.

추천 결과는 자동 선택이나 자동 확정이 아니다. Work Map의 사용자가 확정한 상태가 SOP 생성 입력의 권위 있는 원본이다.

### 2.3 동료 SOP 기반 생성

1. 팀·조직 내 동료를 검색한다.
2. 동료가 작성 완료한 Work Map과 SOP를 읽기 전용으로 미리 본다.
3. 선택한 Work Map과 SOP를 자신의 독립 초안으로 복제한다.
4. Activity와 이후 SOP 내용을 자신의 업무에 맞게 수정·삭제·추가한다.
5. 그 이후는 Task 기반 생성과 동일한 편집·임시 저장·승인 요청 인터페이스를 사용한다.

원본 소유자에게 “템플릿으로 사용됨” 알림을 보내는 기능은 원문에서 선택 사항이며, 개발 일정에 영향을 주면 제외할 수 있다.

### 2.4 기존 작성 내용 기반 생성

1. 구성원이 자신이 과거에 작성한 Work Map과 SOP를 조회한다.
2. 선택한 기록을 새 독립 초안으로 불러온다.
3. 이후는 공통 편집·임시 저장·승인 요청 흐름을 사용한다.

이 경로는 단순히 기존 레코드를 편집하는 기능이 아니다. 원본을 보존하고 새 문서 ID, 새 버전 맥락, 초기화된 승인 상태를 갖는 복제 경로로 구현한다.

### 2.5 구성원 승인 요청과 추적

- 구성원은 작성 완료된 Work Map과 SOP를 승인 요청한다.
- 현재 상태 `대기 중 / 검토 중 / 반려 / 승인`을 확인한다.
- 반려 사유와 구체적 피드백을 확인하고 편집기로 이동해 수정한 뒤 재요청한다.
- 별도 승인관리 페이지는 필수가 아니며, 나의 SOP 화면에서 위 행동을 수행해도 된다.

### 2.6 승인자

- 기본 시나리오는 `1차 직책자 → 2차 SME` 순차 검토이다.
- 승인 대기함은 요청자, 요청일, 우선순위, 상태를 표시한다.
- 조직, 직무, 상태로 필터링한다.
- 전체 승인과 선택 승인을 지원한다.
- Work Map과 SOP를 편집 화면과 구분된 읽기 전용 뷰어로 검토한다.
- 승인하면 다음 승인 단계로 보내거나, 2차 승인인 경우 공식 SOP로 확정한다.
- 반려할 때는 선택형 사유와 자유 서술 피드백을 필수로 받는다.
- 조직 현황에서 구성원의 SOP 작성률과 승인 완료율을 확인한다.

원문 일부에는 “직책자 또는 지정된 SME”라고도 표현되어 있다. 프로토타입은 문서의 역할 제목에 명시된 2단계 순차 흐름을 기본 시나리오로 사용하되, 실제 승인자 배정 정책이라고 주장하지 않는다.

### 2.7 HR

- 전사·조직별 작성 인원, 작성 건수, 승인 완료율을 보여준다.
- 초안, 검토 중, 승인 완료, 반려의 상태별 분포를 보여준다.
- 상세 데이터를 Excel 또는 CSV로 내려받을 수 있다.
- Task 등록 빈도로 Top Task를 산출한다.
- 구성원이 AI 대체 가능으로 판단한 항목 중 승인된 건수를 Task별 Agent화 후보 근거로 집계한다.
- 승인 SOP를 Task별로 모아 대표 표준안 후보를 조회한다.
- Task 그룹의 승인 SOP들을 입력으로 대표 표준안 초안을 생성하고 미리 보는 AI 적용 장면을 제공한다.
- 운영용 군집화·프로세스 마이닝과 대표 표준안 확정은 이후 단계로 구분한다.

원문은 HR 지표가 가안이며 추가될 수 있다고 명시한다. 따라서 현재 프로토타입의 집계 규칙과 분모를 화면에 설명하고, 검증되지 않은 생산성·비용효과 점수나 확률을 만들지 않는다.

## 3. 이미지에서 사용할 수 있는 기능 의미

원문 첨부 이미지는 디자인 레퍼런스가 아니다. 다음 기능 의미만 사용할 수 있다.

- Work Map에서 Task 목록과 Task별 Activity·Skill 관계를 확인한다.
- Task, Activity, Skill 요소를 추가·삭제·선택할 수 있다.
- SOP에서 Activity를 그룹 또는 탐색 단위로 사용한다.
- Activity 아래에 실행 순서, 분기, 시작·종료를 포함하는 Sub Action 흐름을 배치한다.
- Sub Action별 AI 적용 가능성과 사람의 판단을 연결한다.

Sub Action의 업무적 의미와 생성 규칙은 [subaction-semantics-contract.md](subaction-semantics-contract.md)를 따른다. 이미지의 “AI 생성”은 Activity 문장을 무조건 노드 하나로 복사한다는 뜻이 아니라, 확정 Activity를 실행 행동으로 분해하고 직무 맥락상 필요한 보강안을 제안한다는 의미로 구현한다.

이미지의 색상 범례, 세로로 긴 단일 캔버스, 좌측 목록 배치, 노드 스타일, 연결선 형태는 복제하지 않는다. 기존 SOP 캔버스의 가독성·라우팅·편집 성능 원칙을 유지한다.

## 4. 최소 프로토타입 해석

다음은 시나리오를 실제로 시연하기 위한 구현 해석이며 고객의 운영정책 확정값이 아니다.

- 로그인 대신 `member / leader / sme / hr` 데모 역할 전환과 고정된 시나리오 사용자를 제공한다.
- 서버 저장은 현재 `SopRepository` 포트를 유지하고, 실제 DB가 없으면 비영속 in-memory 어댑터임을 표시한다.
- 한 브라우저 세션에서 구성원이 요청한 문서를 승인자와 HR 화면이 동일한 레코드로 조회할 수 있어야 한다.
- 승인 상태는 최소한 `draft → leader-review → sme-review → approved`와 어느 검토 단계에서든 `rejected`를 표현한다.
- 구성원 홈의 `승인 요청 중`은 leader-review와 sme-review를 합산한다.
- 승인자는 자신의 단계에서만 승인·반려할 수 있고, 작성자는 자신을 승인할 수 없다.
- 반려된 문서를 수정할 때 승인 피드백은 보이고, 재요청 시 새 초안으로 돌아가지 않고 동일 레코드의 검토 주기를 재개한다.
- 정교한 권한, 감사 로그, 알림 인프라, 실시간 협업, 생산 DB는 구현하지 않는다.
- 대표 표준안 생성은 선택 Task 그룹의 승인 문서만 사용하고 구성원 개인정보를 제거한 AI 초안·미리보기로 구현한다. 생성 결과를 공식 표준으로 자동 확정하지 않는다.

## 5. 구현 시 유지할 데이터 불변식

- Work Map의 Task·Activity·Skill 스냅샷과 SOP의 Activity·Sub Action 출처 연결을 보존한다.
- 신규 Task SOP의 모든 Sub Action은 정확히 하나의 Activity에 속한다.
- 입력·선행 결과·목적·산출물 자체를 실행 행동으로 오인하지 않는다.
- 기존 Activity 범위 밖의 맥락 기반 행동은 신규 Activity 후보로 먼저 제안하고 구성원이 수락한 뒤 생성에 사용한다.
- 모든 선택 Activity는 하나 이상의 Sub Action으로 커버된다.
- AI Agent화 제안과 구성원의 확정 판단을 분리한다.
- 승인 상태, 편집기 내용 검토 상태, Agent화 확정 상태를 서로 다른 필드로 관리한다.
- 승인 요청 이후 검토 중인 문서는 구성원에게 읽기 전용이다. 반려 후 수정 시작 또는 명시적 회수 정책을 통하지 않고 내용을 바꾸지 않는다.
- 동료·과거 문서 복제는 원본을 변경하지 않고 별도 ID를 만든다.
- 동료 복제는 원본 구성원의 이름, 사번, 조직, 피드백을 복사하지 않는다.
- 과거 문서 복제는 현재 구성원 소유권을 유지하되 승인·검토·Agent화 확정 상태를 초기화한다.
- HR 집계는 저장된 레코드에서 계산하며 화면용 임의 숫자를 만들지 않는다.

## 6. 미확정 항목

다음을 고객 확정 요건처럼 구현하지 않는다.

- 직책자와 SME의 실제 배정 규칙 및 승인 생략 조건
- 우선순위 산식, 승인 SLA, 알림 채널
- 반려 선택 사유의 최종 코드 목록
- 동료 검색의 조직 가시성 범위와 템플릿 공개 승인 주체
- 연도별 버전 명명과 보존 기간
- HR 대시보드의 최종 지표, 집계 기간, 분모
- Task를 Agent화 후보로 판정하는 임계값
- 군집화·프로세스 마이닝 알고리즘과 대표 표준안 확정 권한
- Excel과 CSV의 최종 컬럼 사양
- 실시간 갱신 방식
- 운영 인증, DB, 감사 이력, 개인정보 마스킹 정책

미확정 값이 시연에 필요하면 가장 작은 가역적 샘플 규칙을 사용하고 UI와 코드에서 `프로토타입 기준`으로 표시한다.
